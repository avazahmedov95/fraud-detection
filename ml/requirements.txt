# Training environment, pinned exactly.
#
# Unpinned floors make a model unreproducible: LightGBM, scikit-learn and
# skl2onnx all change numerics across minor releases, so a retrain months later
# yields a different model from the same data and seed, and the metrics quoted
# in the thesis stop being regenerable.
#
# HONEST CAVEAT: these pins record the environment as of 2026-08-15. The
# model.onnx and metrics currently in ml/models/ were produced in July under an
# environment that was never captured and cannot now be reconstructed. Pinning
# fixes reproducibility going FORWARD only. If the reported metrics need to be
# defensible, retrain once on this pinned environment and quote those numbers
# rather than the July ones.
lightgbm==4.6.0
scikit-learn==1.7.2
shap==0.49.1
onnxruntime==1.23.2
onnxmltools==1.16.0
skl2onnx==1.20.0
matplotlib==3.10.8
pandas==2.2.3
numpy==2.1.3
joblib==1.5.3

# Note on numpy: training runs here on numpy 2.x while the Flink image serves on
# numpy 1.24.4. That divergence is harmless precisely because the handoff is
# ONNX rather than a pickled estimator - the exported graph carries no numpy
# ABI dependency. It is also the reason the ONNX parity check (~2e-07) is worth
# keeping in the pipeline: it is what makes the divergence safe to ignore.
