# Generator + producer, pinned exactly to the host environment the reported
# datasets and measurements were produced on (2026-08-15).
#
# The seed alone does not make synthetic data reproducible: numpy's Generator
# guarantees a stable stream for a given bit generator and version, so a numpy
# upgrade can legitimately change the drawn values. Pinning is what makes
# "seed=42" mean the same dataset next year as it does today (the transaction
# ids aside: they are random UUIDs, used by no feature).
numpy==2.1.3
pandas==2.2.3
kafka-python==3.0.7

# The speed runs replayed this kafka_producer.py from inside Docker, where
# kafka-python is 3.0.10 (sink-writer/requirements.txt): timing across the
# host/VM clock boundary errs by about as much as it measures. The pin above
# covers `run.ps1 produce` and `produce-stream`; the producer uses no API that
# changed between the two patches.

# For --encrypt: kafka_producer.py takes payload_crypto.py from stream-processor/,
# which imports this lazily, so a plaintext replay runs without it. Pinned to the
# version the job decrypts with (infra/flink/Dockerfile): both sides must agree
# on the envelope.
cryptography==48.0.0
